## User Story

Como OwnerAdmin o StoreUser, quiero actualizar mi nombre, teléfono y correo, para mantener mis datos al día.

## Precondiciones

- Usuario autenticado con feature `Profile = 70` (`edit-profile.tsx:10`). El guard es `featureLoader`, que **sí** tiene el bypass OwnerAdmin/SuperAdmin (`loaders.ts:89-91`) — a diferencia de `adminFeatureLoader`, ver **H-7**.

## Flujo

1. Ir a la edición de perfil.
2. Cambiar los datos y guardar.

## Aserciones — Playwright (UI)

- [x] El formulario aparece pre-cargado con `fullName`, `cellPhone` y `email` del usuario en sesión (`edit-profile.tsx:20-24`). Verificado en `e2e/edit-profile.spec.ts`.
- [x] El payload incluye `isActive: user.isActive` — la pantalla **reenvía** el estado actual, no lo edita (`edit-profile.tsx:41`). Verificado en `e2e/edit-profile.spec.ts`.
- [x] Éxito muestra `PROFILE.UPDATE_SUCCESS` y **permanece** en la pantalla; no navega (`edit-profile.tsx:54`). Verificado en `e2e/edit-profile.spec.ts`.
- [ ] Fallo muestra `PROFILE.UPDATE_ERROR` (`edit-profile.tsx:55-56`). — Brecha declarada: requiere forzar un error del backend (500).
- [x] Tras el éxito, el usuario en sesión queda actualizado **sin recargar la página** (`updateUser` — `edit-profile.tsx:53`). Verificado implícitamente en `e2e/edit-profile.spec.ts` (el éxito muestra el mensaje sin recarga).
- [ ] `updateUser` **preserva** el `expiresIn` vigente. — Brecha declarada: `expiresIn` no es observable desde Playwright (solo en memoria del auth-store).
- [x] Offline: el formulario deshabilita el envío (`edit-profile.tsx:66` pasa `isOnline` al formulario). Verificado en `e2e/edit-profile.spec.ts`.
- [x] La contraseña nunca viaja en el payload (`UpdateProfilePayload` no la declara — `profile-http-service.ts:4-9`). Verificado en `e2e/edit-profile.spec.ts`.

## Aserciones — .NET E2E (dato)

- [x] `PUT /v1/users/{id}` sobre uno mismo → 200 y campos persistidos.
- [x] Body parcial preserva email y teléfono; `cellPhone` vacío **sí** limpia el valor.
- [x] Omitir `isActive` preserva el estado; un StoreUser con feature `Profile` conserva su propio `isActive`.
