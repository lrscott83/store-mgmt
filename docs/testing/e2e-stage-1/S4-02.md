## User Story

Como OwnerAdmin o StoreUser, quiero cambiar mi contraseña, para recuperar el control de mi cuenta si sospecho que se filtró.

## Precondiciones

- Usuario autenticado con feature `Profile` (`change-password.tsx:10`).

## Flujo

1. Ir a la pantalla de cambio de contraseña.
2. Ingresar contraseña actual y nueva; enviar.

## Aserciones — Playwright (UI)

- [x] El payload es exactamente `{ oldPassword, newPassword }` (`change-password.tsx:19,25`; `profile-http-service.ts:11-14`). Verificado en `e2e/change-password.spec.ts`.
- [x] Un cambio exitoso **cierra la sesión** y redirige a `/login` — el redirect lo hace `logout()`, no la pantalla (`change-password.tsx:28`; `auth-store.ts:303-321`). Verificado en `e2e/change-password.spec.ts`.
- [x] Tras el logout, `AUTH_MODEL` desaparece de `localStorage` (`auth-store.ts:307`). Verificado en `e2e/change-password.spec.ts`.
- [ ] Tras el logout, la DEK en memoria queda liberada (`clearDek()` — `auth-store.ts:312`). — Brecha declarada: la DEK no es observable desde Playwright (solo en memoria del proceso).
- [ ] Un fallo muestra `PROFILE.UPDATE_ERROR` y **NO** cierra la sesión (`change-password.tsx:29-30` — `logout()` está solo en la rama de éxito). — Brecha declarada: requiere forzar un error del backend (500).
- [x] Offline: el envío está deshabilitado (`change-password.tsx:39`). Verificado en `e2e/change-password.spec.ts`.
- [x] Tras el cambio, la contraseña **anterior** ya no permite iniciar sesión y la nueva sí. Verificado en `e2e/change-password.spec.ts`.

## Aserciones — .NET E2E (dato)

- [x] Cambio propio → 200 y re-login con la nueva contraseña funciona.
- [x] Contraseña actual incorrecta → 400.
- [x] Contraseña nueva débil → 400.
- [x] Un StoreUser sin permiso cambiando la de otro → 403.
- [x] Un OwnerAdmin del mismo tenant → 200; de otro tenant → 404.
