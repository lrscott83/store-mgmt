# Online order PaidAt (web catalog)

Objective: record when an online (web catalog) order became paid.
Branch: `feat/online-order-paid-at` (base `dev`). Delivery: single work unit. Runner: `dotnet test` (backend), `pnpm test` (frontend).

## Specs

- **S1** — Add a `PaidAt` column to the online order (the order created from the web catalog) that records the date it was paid, as durable evidence.
  - User's words: "Adicionar la columna PaidAt en la orden del catalogo web para que registre la fecha de cuando se pago y tener constancia."
  - Acceptance: `Domain.Entities.Orders.Order.PaidAt` exists, nullable `DateTime?`, persisted as its own column.
- **S2** — `PaidAt` is written by the payment gate only.
  - Marking paid (`ChangePaymentStatus(Paid)`) stamps it; a second "paid" mark on an already-paid order does not move the original date.
  - Moving the order to `Entregado` (which pays it) stamps it too.
  - Returning the payment to `Pending` clears it: the record must not claim a payment the order no longer has.
- **S3** — The migration is the source of truth; the SQL script is generated from it (repo convention).
  - EF migration `Add-Order-PaidAt` + `scripts/41-20261026-Add-Order-PaidAt.sql` generated by `dotnet ef migrations script <previous>`, with the `ON CONFLICT` history fix and verification queries.
- **S4** — *(assumption A1)* The date is readable by the owner: exposed in `OnlineOrderListItemDto` / `OnlineOrderDetailDto` and rendered in the POS order detail modal ("Pagado el …") only when the order is paid.
- **S5** — Existing behavior is untouched: POS orders (`Order.Create`) never get `PaidAt`; status/payment semantics, filters and stats stay the same.
